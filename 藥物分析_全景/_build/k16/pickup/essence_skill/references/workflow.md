# 工作流程、QA 清單與常見錯誤

## 一章的流程

1. **盤點 ①**：列出閘門、每條 L（編號、名稱、推導鏈開頭）、每條 L 掛的藥、結構族（骨架、SMILES、鑰匙）、本章藥卡清單。
2. **查字根**：每顆藥從字根資料庫查字根；查不到就留空，不自創。
3. **寫 ⓪**：
   - 先定中心比喻與副標。
   - 門派＝閘門；每個分支寫清楚掛哪幾條 L。
   - 每類一列：類別名稱 → 字根 → 骨架（英文＋代表藥 SMILES＋鑰匙）→ 比較軸 → 每藥 Δ → 共同代價 → 連動。
   - 圖例：紅框、綠框各代表什麼。
   - ⚠ 比喻失效提醒：跨門派的藥、和直覺相反的地方。
4. **自動檢查**（全部要通過）：
   - ⓪ 用到的每個 L 都存在於 ①。
   - 類別自己的 L 是分支 L 的子集。
   - 每類至少一顆藥。
   - SMILES 能解析；鑰匙 SMARTS 真的對得到。
   - 結構節點若是高頻藥，分子式要和資料庫一致。
5. **產生 PDF**：links 統計、missing＝0；版面檢查（文字不出界、不跨框、不重疊、結構圖不出框）。
6. **看渲染圖**（低解析度整頁＋局部放大）：
   - 門派方塊、分支框的文字有沒有溢出。
   - 外觀框的結構圖是否清楚、鑰匙上色是否正確。
   - 左右兩側是否平衡（自動分配仍太長時，檢查是否有門派分支過多）。
   - 中心圓的副標有沒有超出圓。
7. **commit、push**：每批章節做完就推，不累積。

## 常見錯誤（本 repo 實際遇過）

| 症狀 | 原因 | 修法 |
|---|---|---|
| 鑰匙沒對到 | 用了資料庫 SMILES，芳香性或寫法和 SMARTS 不同 | 改用結構族裡的 SMILES，或把 SMARTS 寫寬一點（例：`NC(=O)N(c)c`） |
| 分支方框裡 L 連結超出右邊 | 一個分支掛太多 L | 讓 L 列表自動換行（已內建） |
| 門派方塊文字溢出 | 標語太長、L 太多 | 標語與 L 列表自動換行，方塊依內容長高（已內建） |
| 中心圓文字超出 | 副標太長 | 副標壓到兩行內，例：「壁、70S、自製葉酸、拓樸酶、膜｜…」 |
| `risk` 參數報錯 | 括號放錯層，`risk=` 被傳給門派 | `risk=` 要放在分支 `BR(...)` 的最後 |
| 字根膠囊出現怪字 | 字根資料庫回傳的是分類標籤（例：「Class I 舊藥」「X＝O：-hydramine 等」） | 只用真正的字根，或留空 |
| 類別名稱前面多一個 `~` | `~` 只給藥丸用 | 類別名稱寫成「NSAID 共同代價」之類 |
| 借來的別章藥連到本章同號的 L | 沒指定它在本章的位置 | 借藥時一併寫本章的 L，或不連 L |
| 一顆藥同時出現在兩類 | 機轉真的跨兩條線 | 允許，但在 ⚠ 比喻失效提醒寫明 |

## 驗收標準

- 每章：⓪＋⓪→①＋①～⑤＋舊版，全部超連結 missing＝0。
- 每類一列，外觀框有類別名稱。
- 所有骨架、官能基、胺基酸位置是英文。
- 「考 n」全部來自題庫自動比對。
