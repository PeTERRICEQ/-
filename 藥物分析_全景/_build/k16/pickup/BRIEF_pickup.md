# 藥分 pick up 版（v2.0）試做說明書

讀者：台灣藥學畢業生，準備藥師一階。INFJ，偏好第一性原理與跨領域類比，不愛死背。

## 一、使用者訂的 pick up 原則（原文照錄，這是最高規範）

■ 名字的由來
英文 pick up 在字典裡有好幾個意思：撿起、接收訊號、學會技能、開車接人。
如果卡片寫「pick up：撿起、接收訊號、學會、接人」，讀者就得死背 4 個互不相干的碎片。
但它們其實只有一個本體：「一個東西從他處移到我處」。
放到地板的語境就是撿起，放到電波就是接收，放到技能就是學會，放到乘客就是接人。
→ 講義的工作就是找出本體，先寫本體，再讓例子從本體長出來。

■ 規則
1. 向量走在例子前面。先寫一句本體，再列投影。讀者看每個例子時，要能立刻回答「它為什麼屬於這個分類」：腦袋拿例子和向量核對，核對得上就記住了。
2. 本體必須是真正的上游原因；寫得太下游，投影會推錯。（反例：acetazolamide 寫「把 HCO₃⁻ 倒進尿 ⇒ 體液減少 → 降眼壓」是錯的；往上提一層寫成「卡住碳酸酐酶＝全身 HCO₃⁻ 生產線停工」，就全部通了。）
3. 用途和代價放在同一組投影裡，不要拆成「優點欄、缺點欄」：它們常是同一個向量落在不同語境。用顏色區分（治＝綠、價＝紅、性＝藍灰）。
4. 一個單位最多 3 個引擎。真的有兩三個獨立原因，就各寫一個本體、各掛投影，不要硬擠成一句。
5. 推不出來的就老實放進「孤點」，不要編假因果；被硬掰的連結在考場會反咬。
6. 分清「機轉橋」（真因果，可以推題）和「記憶鉤」（只是好記，要標明不能推題）。

■ 怎麼檢查本體寫對了
- 遮住測試：只看本體，遮住投影，一條一條推出來。推不出來的那列 = 本體不夠上游，或者該搬去孤點。
- 上游測試：某條投影需要另一個不相干的原因才解釋得通 → 本體往上提一層，或那是第二個引擎。
- 反向測試：拿一道考題的題幹（症狀、條件、現象），要能一路追回本體。

■ 使用者給的藥分示範（格式示範，內容要依講義與題目核對）
逆相 HPLC 本體：【分子在「油的固定相」和「水的流動相」之間分配，越油留越久】
- 性：有機比例↑ → 流動相變油 → 全部提早出峰
- 性：弱酸在高 pH 解離 → 變水溶 → 早出 → 酸性藥用酸性流動相壓住解離
- 治：離子對試劑把帶電藥包成中性的「油」→ 留得住
- 第二引擎【鹼性胺與 silanol 的離子作用】→ 價：拖尾 → 解法：end-capping、低 pH、加 TEA
非水滴定本體：【拿掉水這個「搶質子的對手」→ 弱鹼、弱酸被放大到滴得出來】
- 治：弱鹼藥溶在 glacial acetic acid、用 HClO₄ 滴；弱酸溶在 DMF 等、用 NaOCH₃ 滴
- 價：水分要除乾淨（水會回來搶質子）
- 性：hydrohalide 鹽的 Cl⁻ 在醋酸中太弱 → 先加 mercuric acetate 換成 acetate 再滴

■ 一句話總結：每個學習單位只准有一到三個本體；所有用途、代價、條件都必須是本體在某個語境下的投影；例子永遠排在向量後面；推不出來的才進孤點。

## 三、成品結構（每章 3 頁＋接上 v1.1）
- **p1 ① 本體推導版**：legend → 引擎 E1–E3（最多 3 個）→ 必要時一個「共用引擎」方塊（L="共用"，例如「面積比＝濃度比」，標明它是全書共用的本體）。投影排在本體後面，治價性混在同一組、用顏色分，不要分欄。每條投影的出處寫規則代號與題數或代表題號。類比都要標 橋 或 鉤。
- **p2 ② 零件向量卡**：該章考過的零件、試劑、溶劑，每張一個本體＋投影＋孤點。卡片的本體要能指回 p1 的哪個引擎（在 vec 裡寫「（E2 的落地）」之類）。依 16 年被考次數排序，exam 寫題數。
- **p3 ③ 孤點與驗收**：孤點清單（標考次）；遮住測試結果表（每個引擎：可推題數、要第二引擎題數）；推不出來的題號與原因；3 個反向測試示範（拿真實題幹一路追回本體）。
- 字級每頁 ≥ 12.5px；左右欄高度接近；無溢出。

## 四、逐題遮住測試（必做，這是驗收）
對你負責章的每一題（ch[0] 屬於該章），只看你寫的本體（不看投影、不看 v1.1），判斷：
- `E`：決定答案的引擎（E1／E2／E3／共用／孤點）
- `t`：`Y`＝只看這個本體就推得出官方答案；`2`＝要兩個本體合用（寫出哪兩個）；`N`＝推不出，進孤點
- `why`：一句推導（Y）或推不出的原因（N）
寫成 JSON：`/home/user/-/藥物分析_全景/_build/k16/pickup/<key>_mask.json`，格式 `{"<id>": {"E":"E1","t":"Y","why":"..."}}`，用 python 驗證題數。
目標：Y＋2 ≥ 90%；N 的題都要在 p3 孤點清單裡。推不出來就老實標 N，不准編假因果。若某個引擎的 N 很多，代表本體不夠上游，回去改本體再測一次（報告裡寫你改了什麼）。
另外做「舊題找本體、新題驗收」：說明你的本體是否只靠 100–107 年的題就寫得出來；108–115 年的題中 t=Y/2 的比例是多少。

## 五、寫作
台灣繁體中文，短句、白話、主動語態；英文專有名詞保留英文。不要用破折號插入語、「不是 X 而是 Y」句型、引號包自創名詞。數字、方向、官方答案要和題目一致；官方答案與原理矛盾時寫「官方選…」並一句說明。不要改 lib.py、print.js、cover.py 和任何不屬於你的 spec；需要產生器新功能就在回報裡說。不要 git commit。
