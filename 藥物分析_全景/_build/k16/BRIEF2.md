## 要做的事
1. 逐題讀完你的所有題目（含選項與答案）。每題判斷：
   - `ax`：決定答案的那一軸（1–5），必要時加第二軸，例如 [1] 或 [5,2]。
   - `k`：**生成規則代號**（章內自己編，如 `uv.R1`）。生成規則＝一條因果句，轉一下就能生出這題和同類題，例如「共軛越長 → λmax 越長、ε 越大」。不同題用同一條規則就給同一個代號。規則要抽象到「能生出別的題」，但具體到「看到題目就知道怎麼用」。只能硬記的事實（數字、人名、試劑顏色）歸到 `章.A<n>` 錨點代號，同一群錨點可以合併成一個代號（如 `id.A1 鹵素離子沉澱顏色`）。
   - `cov`：現有精華頁能否直接作答：Y／P（要再推一步）／N（頁面沒有）。傳統分析各章沒有精華頁，一律填 `-`。
2. 用 python 把逐題結果寫成 JSON：`/tmp/claude-0/-home-user/27534a2c-1e30-5d14-9da3-4fcd4627ac86/scratchpad/k16/w2/<group>_q.json`，格式 `{"<id>": {"ax":[1], "k":"uv.R1", "cov":"Y"}, ...}`；以及規則表 `.../w2/<group>_k.json`，格式 `{"uv.R1": {"rule":"一句因果", "type":"R" 或 "A", "ax":[2]}, ...}`。所有題都要出現；寫完用 python 驗證題數。
3. 寫每章報告到 `.../w2/<group>.md`。每章一節：
   - **一句 Ni**：能生出整章最多題的一句話（≤40 字），要是第一性原理，可附一個跨領域類比。
   - **生成規則排行**：表格列 代號｜規則｜題數｜代表題號（2–3 個）｜五軸。把規則照題數排序，標出累積覆蓋率。目標：最少幾條規則覆蓋 80%？
   - **錨點**：真的只能記的事實，列出每條被考幾次。越少越好；能從規則推出的不准列成錨點。
   - **五軸分布**與**年份趨勢**（100–107 vs 108–115 題數；新出現或消失的規則）。
   - **精華頁比對**（儀分）：cov=N 的題號與缺的內容；頁面上 16 年沒考過、可以刪掉或縮小的內容。
   - **建議**：這章精華頁怎麼改（加什麼、刪什麼、哪個方塊換成哪條規則），具體到可以直接改 spec。
